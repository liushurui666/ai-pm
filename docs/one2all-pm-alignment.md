## 实现约束

- 所有跨表关系优先使用稳定 ID，历史仅有项目名称的数据只在当前工作区存在唯一候选时回退；同名项目一律拒绝猜测授权。
- 项目/版本详情统一按项目 ID 和版本子树过滤，避免同名项目、父子版本或其他工作区的数据串入。
- 项目成员权限由访问级别、职能角色和需求作用域共同决定；页面按钮、任务看板与排期拖拽使用同一套有效权限结果。
- 非全权成员只读取自己有显式项目权限或承担版本、需求、任务职责的项目；项目列表、业务记录与治理快照使用同一可见项目集合。
- 需求和版本负责人指派在业务记录事务内补齐项目成员身份；只读/评论成员自动升级为项目成员，取消指派不自动降权。
- 需求负责人、设计负责人和开发人员分别按字段与动作矩阵授权；任务经办人和需求参与者可更新任务，但不能删除或改绑项目关系。
- 交付标签目录按版本隔离；目录允许显式清空，同一版本节点不能重复使用同一标签，删除目录项不改写历史节点快照。
- 任务优先级新写入统一使用“普通”，所有数据库读取、种子、AI 动作和文档拆解入口兼容历史“中”；风险等级与需求优先级保持各自语义。
- 项目负责人交接、项目成员写入和需要审计的动作在同一事务中完成；后台 AI 动作在入队和执行时各校验一次当前成员权限。
- 删除空版本可直接完成；有关联数据的版本迁移到项目内唯一兜底版本，无法唯一定位时拒绝删除，不做跨项目迁移。
- 项目/版本健康度由周期、进度、风险和任务完成情况派生，表单不允许手工写入派生结果。
- production 进程内复用同一个 PrismaClient；MariaDB 默认池上限为 5、最小空闲为 1，并用连接回归脚本守住 SSR 与 API 并发导航的稳定性。

## 验收门槛

- 项目集、项目/版本、需求、任务的新字段可创建、编辑、刷新后回显。
- 项目/版本进度来自完成任务数，健康度可解释且不能手工覆盖。
- 从需求下钻任务后，刷新、分享和浏览器前进/后退仍保留同一需求筛选；跨工作区或不可见需求不会回放。
- 项目详情五个 Tab 均使用真实数据；空态、正常态和长内容不溢出。
- 成员权限、负责人交接、交付节点快捷编辑均调用真实服务端接口并产生动态记录。
- 服务端拒绝 viewer/commenter 以及无项目权限成员的写请求。
- `pnpm lint`、`pnpm build`、PM 定向 smoke 通过。
- 使用 Chrome DevTools MCP 验证桌面和 390px 窄屏、主要抽屉开关、保存动作、控制台与网络请求。
